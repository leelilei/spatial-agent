# SpatialAgent Research Plan v2 审稿式评审总结

> 评审对象：`spatial_agent_research_plan_v2.md`
> 评审视角：顶会匿名审稿人 / 方法论文评审
> 评审立场：严格但建设性，关注可发表性而非仅创意吸引力

---

## 一、总体判断

`v2` 相比 `v1` 有明显进步，尤其体现在以下三点：

- 主张强度显著收缩，不再轻率宣称“证明”空间构型因果塑造社会涌现
- baseline 设计明显增强，开始正面回应“只是更多上下文”与“只是 prompt engineering”的质疑
- 实验结构从并列堆叠改为三阶段递进，逻辑上更接近一篇可 defend 的方法论文

从专业审稿角度看，这已经不再是“只有一个好故事”的 proposal，而是一个**有潜力形成强论文骨架**的研究计划。

但如果以正式投稿标准衡量，`v2` 目前仍更像一份**很强的研究蓝图**，而不是一份已经达到“高置信可执行、评估闭环充分、理论与指标完全自洽”的论文级方案。最大风险已经不再是 claim 过大，而是：

- 评估规则中仍可能存在“把结论写回指标”的循环定义
- 空间指标的文本化重定义还不够严密
- `Topology-Only` 对照与 `SpatialAgent-Lite` 的可比性仍有潜在混淆
- 多地图实验仍可能被解释为“地图个例效应”而非“构型规律”

### 审稿结论

如果这是一个研究计划，我会给出：**强烈建议继续推进，但在正式实现前需完成一次方法学收口**。

如果这是一个准备直接写成顶会论文的方法部分蓝图，我的建议是：**Major Revision**。

---

## 二、主要优点

### 1. 研究问题收缩得当，主线更清楚

`v2` 最大的改进是研究问题被重新组织为三层：

- 表征是否有效
- 认知效应能否与拓扑必然效应分离
- 哪些指标最稳定

这比 `v1` 直接冲向“空间构型塑造社会涌现”稳健得多。尤其是 `RQ2` 明确提出要排除 `topology-driven encounter opportunity`，这说明计划已经从“好 intuition”走向“方法识别问题”。

### 2. baseline 体系明显更专业

`No Space / Name Only / Rich Non-Spatial / Raw Numeric / Neutral Structural / Shuffled Signal` 这一组设计非常关键，已经具备了论文里最有说服力的 ablation 梯度雏形。特别是：

- `Rich Non-Spatial` 对冲了“更多上下文”质疑
- `Shuffled Signal` 对冲了“只要有点环境描述就行”质疑
- `Interpretive vs Neutral Structural` 对冲了“暗示性 prompt 泄漏”质疑

这部分是 `v2` 最强的一块，也是最值得保留为论文主实验主线的部分。

### 3. 对理论迁移风险的自觉性增强

`v2` 不再把 Space Syntax 当作可以直接搬运的现成真理，而是明确承认两个理论跳跃：

- 从真实人类到 LLM Agent
- 从物理空间到文本空间

这种写法更成熟，也更像审稿人愿意接受的姿态。你没有再把理论正确性当作前提，而是把它转化为待检验命题，这一点是正确的。

### 4. 负面结果路径被认真纳入

计划中多次写明：

- 如果 Neutral Structural 不如 Interpretive，有方法论价值
- 如果 SpatialAgent 不优于 Topology-Only，仍可转向 topology-driven effect 论文
- 如果阶段1失败，本身可形成一篇关于 LLM 空间推理局限性的负面发现论文

这显示出计划具备研究设计上的韧性，而不是一条路走到底。

## 三、主要问题

## 1. 结构化行为标注仍存在“循环定义”风险

这是我认为 `v2` 当前最重要的问题。

你在 `6.1` 中提出用“结构化行为标注”替代开放评分，这个方向是对的。但你当前给出的“空间-行为适配规则表”仍然非常接近把理论假设直接写成评估标准，例如：

- 高 `Openness` + 多人在场 -> 公开讨论、主动搭讪
- 低 `Openness` + 少人 -> 低声交谈、分享秘密

这会让审稿人产生一个直接质疑：

> 你最后测到的是 Agent 是否符合你事先写好的规则，而不是它是否真的更 believable。

换句话说，如果评估规则本身编码了你的理论预期，那么实验就会从“检验假设”退化为“计算模型是否服从假设模板”。

### 为什么这是严重问题

- 它会削弱 `RQ1` 和 `RQ3` 的独立性
- 它让结构化评估从“去偏”变成“换一种方式写回偏好”
- 审稿人会认为你只是把原本的 prompt 泄漏，转移到了 evaluation rubric

### 建议

- 将“行为适配规则表”改为更弱、更描述性的标签体系，而不是规范性的适配判断
- 让独立标注者先仅标行为类型与环境事实，不先定义“适配/不适配”
- 将“适配性判断”拆成第二阶段分析，而不是直接写入标注协议
- 至少加入一部分人类 blind coding，验证你的规则不会系统性偏向主方法

如果不改，这一点会持续成为整篇论文最明显的 methodological vulnerability。

---

## 2. `Topology-Only` 对照的定义仍不够干净

你在 `RQ2` 和 `Exp2` 中把 `Topology-Only` 作为分离“拓扑效应 vs 认知效应”的关键对照，这个方向正确，但当前定义还存在模糊性。

文中一方面写：

- `Topology-Only` 使用与 `SpatialAgent` 相同的移动算法

另一方面又写：

- `SpatialAgent-Lite` 的核心机制包括 `Spatial Perception` 和 `Spatial Action Sampling`
- `SpatialAgent` 在移动/目的地选择上使用 LLM CoT 推理

这里的疑问是：

> `Topology-Only` 到底共享哪些空间信息？

如果它在移动阶段仍隐式使用了空间特征，那它就不是严格意义上的 “topology-only”。
如果它不使用这些特征，那它与 `SpatialAgent` 的差别就不仅是“对话时是否注入空间信息”，而是“决策机制整体不同”。

### 这会带来什么问题

- `RQ2` 的“认知效应分离”会变得不干净
- 审稿人无法判断你分离的是哪一层认知
- 行为差异可能来自 mobility policy，而不是 interaction policy

### 建议

在计划中明确拆分两个层级：

- `movement policy`
- `interaction policy`

并对每个 baseline 明确说明：

- 是否可访问空间指标
- 是否可访问仅拓扑邻接
- 是否可访问动态在场信息
- 是否使用相同候选生成/重排序机制

最好把所有 agent 条件整理成一个“信息访问矩阵 + 决策模块矩阵”。只要这张表一清楚，`RQ2` 的可信度就会明显提升。

---

## 3. `Openness` 的文本化重定义仍需更严格的理论防守

`v2` 已经意识到 `Visual Depth` 在文本图世界里不能原封不动使用，因此改成了 `Openness`。这是进步。但当前写法还不够让一个严厉审稿人完全信服。

关键问题有两个：

### 第一，`visible(i, j)` 的定义仍不充分

在文本离散图中，什么叫“可观察到”？

- 是同一直线？
- 是无中间遮挡？
- 是同一房间内？
- 是路径不弯折？
- 是地图作者手动标注？

如果没有清晰、可复现的 visibility annotation protocol，`Openness` 很容易被视为人工设定出来的隐私标签，而不是严谨指标。

### 第二，`Openness` 与 `Connectivity` 可能高度相关

你已经意识到共线性问题并提出 `r > 0.8` 时合并讨论，这很好。但仅靠事后报告相关矩阵还不够，因为：

- 在 20 节点手工地图里，这两个量可能天然纠缠
- 一旦高度相关，关于“视线”和“连通”的行为解释就会变得不可区分

### 建议

- 在研究计划中补上 `visible(i, j)` 的精确定义与标注流程
- 明确哪些图结构会造成 `Connectivity != Openness`
- 尽早构造至少一个最小例子，证明这两个指标在你的环境中确实可分离
- 如果最后分不开，应主动把相关假设改写为联合因素，而不是坚持单指标解释

---

## 4. 多地图实验仍可能被质疑为“地图个例效应”

`Exp3` 相比 `v1` 已经更严谨，因为你加入了每种地图上的 `Topology-Only` 对照，并把重点放在“认知增量”而不是“地图差异本身”。这非常正确。

但问题仍然存在：

- 你仍只有三张主地图
- 它们仍是手工设计
- 每张地图仍同时改变多个结构属性

这意味着审稿人仍然可以说：

> 你测到的是这三张具体地图的 idiosyncratic effect，而不是某类空间构型的一般规律。

`Exp3-Minimal` 试图解决这个问题，但目前仍然偏弱，因为它只列出了两个 minimal-pair 思路，没有说明：

- 每组最小对实验会生成多少实例
- 是单个 pair，还是一族 pair
- 是否有程序化生成与筛选标准

### 建议

- 把 `Exp3-Minimal` 从“补充实验”升级为主实验的一部分
- 至少为每种操控生成多个实例，而不是单一 pair
- 明确采用何种约束生成地图，以避免作者主观挑图

如果不这样做，`Exp3` 更适合作为 demonstration，而不适合作为 strong evidence。

---

## 5. 阶段1的成功标准需要更细，不能只看“准确率 > 70%”

`5.0` 中的预实验是必要的，但当前 gate 太粗。

你现在的判断规则是：

> 如果 LLM 在 Neutral Structural 描述下回答准确率 < 70%，则调整描述或更换模型。

问题在于，“空间推理能力”并不是单一能力。至少应区分：

- 对数值和排序的理解
- 对 visibility / connectivity 的理解
- 对空间属性向行为 affordance 的迁移推理

一个模型可能：

- 能复述“有几个出口”
- 但不能稳定地把它转化为行为差异

### 建议

把阶段1拆成两个层级指标：

- `comprehension accuracy`：是否读懂结构描述
- `behavioral inference consistency`：是否据此做出方向一致的行为推断

如果只用一个笼统准确率门槛，阶段1通过并不能充分支持进入阶段2。

---

## 6. 统计计划比 v1 强很多，但仍有几个不一致点

`v2` 在统计方法上明显更成熟，但计划内部仍有一些需要统一的地方：

- `6.3` 中阶段2写 `Linear Mixed-Effects Model`
- 阶段3又写 `ANOVA + post-hoc Tukey HSD`
- 但 `Exp3` 的核心问题明明也是 repeated runs + layout × agent_type 交互，更像 mixed-effects 问题

另外，人类评估部分使用：

- Likert 1-7
- 配对 t 检验

这不是不能用，但在更严格的审稿场景下，可能会被要求：

- 使用 ordinal model
- 或至少说明为什么将其近似为连续变量

### 建议

- 将统计计划统一成一套主分析框架
- 优先用 mixed-effects 贯穿阶段2和阶段3
- 对人类评估提前说明主分析与稳健性分析各是什么

这不是致命问题，但属于正式投稿前必须收口的 technical hygiene。

---

## 四、次要问题

### 1. 计算预算和时间线仍然偏乐观

`v2` 已经比 `v1` 现实，但总调用量约 `555,000` 次，外加：

- prompt 迭代
- 失败 run 重跑
- 标注调试
- 人类实验材料打磨

实际成本和时间大概率会继续上浮。建议把时间线里显式加入：

- pilot debugging 周期
- annotation guideline 调整周期
- 失败实验重跑预算

### 2. `Neutral Structural` 可能仍然过长

从可解释性角度，客观结构描述是好的；但从 LLM 长程模拟角度，它可能仍带来：

- token 冗余
- 数值负担
- 注意力稀释

建议尽早测试更紧凑的 schema-like 表征，例如固定槽位模板，而不只是一段完整自然语言。

### 3. 投稿定位仍需二选一

目前计划在叙事上同时追求：

- 理论桥接
- 架构方法
- 社会模拟发现

这三者兼容，但正式论文仍要有一个主重心。否则写作时会出现“每部分都重要，但页数都不够”的问题。

我的建议是：

- 若投 `AAMAS`：主打“多 Agent + topology vs cognition 分离”
- 若投 `AAAI`：主打“空间结构化表征与严格 baseline 协议”

## 五、我会给出的评分

以下评分是按“顶会匿名审稿人阅读研究计划/论文蓝图”的标准给出，不是对 idea 吸引力的主观喜恶。

| 维度 | 评分（5分制） | 评语 |
|------|--------------|------|
| 新颖性 | 4.5/5 | 跨建筑学 Space Syntax 与 LLM multi-agent 的连接非常新 |
| 重要性 | 4.0/5 | 问题成立，且对游戏 AI / 社会模拟都有潜在价值 |
| 方法清晰度 | 3.8/5 | `v2` 比 `v1` 清楚很多，但关键对照定义仍需收口 |
| 评估严谨性 | 3.2/5 | baseline 强了很多，但 evaluation rubric 仍有循环定义风险 |
| 理论扎实度 | 3.4/5 | 理论姿态明显成熟，但文本空间中的指标迁移还需更强论证 |
| 可执行性 | 3.5/5 | 可做，但工程量与实验量都较大，需进一步聚焦 |

### 综合判断

这是一个**值得投入实现的项目**，而且 `v2` 已经进入“有可能产出一篇像样论文”的区间。

但如果问我：

> 这份计划今天就能直接作为 conference-ready 的 method blueprint 吗？

我的答案是：

**还不行，离“可发表级严谨”还差最后一轮方法学打磨。**

## 六、最优先修改建议

如果只允许我给三条最高优先级建议，我会给这三条：

### 1. 重写评估协议，避免把假设直接写进适配规则

这是当前最大风险。优先级最高。

### 2. 为所有 agent 条件补一张“信息访问矩阵”

把每个条件能看到什么、能用什么、在哪一层使用空间信息，写得一清二楚。这样 `RQ2` 才真正站得住。

### 3. 把 `Exp3-Minimal` 做实，而不是做成点缀

如果想说服审稿人相信“空间属性”而不是“这三张地图”，最小差异对实验必须更强。

---

## 七、最终结论

从专业审稿视角看，`v2` 是一次成功的大修。它已经把 `v1` 中最危险的几个问题正面处理掉了：claim 收缩、baseline 增强、负面结果纳入、理论跳跃显式化、统计计划升级。这些都说明你不是在“给 idea 补包装”，而是在认真把项目往可审稿的方向推进。

但 `v2` 也暴露出一个新阶段的问题：现在最关键的不再是“讲什么故事”，而是**如何让识别、指标和评估真正独立于你的预设理论**。如果这一层处理得好，这个项目会非常有辨识度；如果处理不好，审稿人仍然会把它归类为“设计精巧但评估自证”的工作。

我的最终建议是：

**不要急着再扩展内容，先把方法边界收紧，把 evaluation 和 control 真正做干净。**
