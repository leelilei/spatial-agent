# 个人学习工作台 PRD（Personal Learning Workbench）

> 版本：v0.1（草稿）　日期：2026-06-14
> 作者：用户 + Claude
> 状态：需求已对齐，待评审后进入开发

---

## 1. 背景与目标

用户是计算机零基础学习者，目标是「看懂并能跑 AI 项目」，正在跟 MIT 6.100L 学 Python，
材料已下载到本地 `0-Basic/MIT-6.100L/`。

现在希望有一个**本地网页工作台**，把「学进度 + 看材料 + 做作业 + 被点评」整合到一处，
让学习有掌控感，也让 Claude 能理解学习情况、给出针对性反馈。

**一句话目标**：打开一个本地网页，就能看到「我学到哪、下一步学什么、在这里做作业、做完被 Claude 点评」。

### 衡量成功（North Star）
- 用户每周愿意打开它，并在里面完成至少 1 次「做作业 → 被点评」的闭环。
- 用户不再需要手动改 markdown 表格来记录进度。

---

## 2. 目标用户与典型场景

**唯一用户**：本人（单机、单用户、本地使用）。

**典型一次使用（用户故事）**：
1. 双击启动（或敲一句命令），浏览器打开工作台。
2. 首页看到五阶段进度，明确「今天该看 Lec 5」。
3. 点 Lec 5 → 打开本地讲义 PDF / 代码，看完打勾。
4. 进入「作业」→ 做 Lec 5 配套题（6.100L 的，或 Claude 出的）。
5. 在网页里写 Python 代码，点「运行」立刻看结果；自带测试的题能看到对错。
6. 点「提交」，答案存到硬盘。
7. 到 Claude Code 终端说「帮我看看这题」，Claude 读答案、写点评。
8. 回工作台看到 Claude 的点评，订正或进入下一题。

---

## 3. 非目标（明确不做 / 留待后期）

- ❌ 多用户、登录、云同步（永远单机单人）。
- ❌ 移动端适配（桌面浏览器即可）。
- ❌ 网页内直接与 Claude 对话 → **二期**（需接 Claude API + key + 计费）。
- ❌ 复杂依赖的作业（需要 GPU/大库的）→ 基础阶段用不到。
- ❌ 替代 IDE / 大型项目开发 → 它只服务「学习 + 小作业」。

---

## 4. 功能需求

优先级：**P0 = MVP 必做**，**P1 = 锦上添花**，**P2 = 二期**。

### 模块 A：五阶段路线图 + 进度（P0）
- 可视化 5 个纵向阶段 + vibe coding 横向线。
- 每个阶段一个进度条（按已打卡项 / 总项数算百分比）。
- 一眼看到「整体走到哪、当前在哪个阶段」。

### 模块 B：课程清单 + 一键开文件（P0）
- 列出 6.100L 全部 26 节课，每节带 ✅/🔶/⏸️ 标签（沿用学习地图）。
- 每节有**两种完成状态**（见模块 G）：👁️ 看过（自报）/ ✅ 学会（须过检查点）。
- 点击直接打开本地 `lectures/lecXX_notes.pdf` / `lecXX_code.py`。
- 显示该节配套的视频链接（在线看）。

### 模块 G：完成确认机制（P0，关键）

**要解决的问题**：「打勾」只代表「我点了」，不代表「我学会了」。要让进度可信、
让 Claude 能真正确认掌握程度，需要一个基于**证据**的确认机制。

**两态模型**
| 状态 | 怎么达成 | 含义 |
|------|----------|------|
| 👁️ 看过 | 用户自己打勾（零门槛） | 看完视频/讲义 |
| ✅ 学会 | **通过该课的「检查点」** | 有证据证明掌握 |

**检查点（checkpoint）**：每节课配 3-5 题，两类混合
1. **自动判题**（Pyodide 当场跑测试，即时对错）——如 Lec 1「预测 `type(5)` 结果」「写一句赋值并打印」。
2. **理解题**（Claude 读后点评）——如「用一句话说说『变量』是什么」，判断真懂还是死记。

**判定规则**：自动题全过 **且** Claude 对理解题点头 → 标记 ✅「学会」，
并在 `progress.json` 记录证据（检查点 id、日期、Claude 批注）。

**检查点题目来源**
- 6.100L 自带「手指练习」（`finger-exercises/` 已下载）改造而来。
- Claude 针对该课核心概念补充出的小题。

**严格度（可调，默认「轻检查」）**
- 默认：代码小题 + 1 道理解题（约 5-10 分钟/节）。
- 调轻：只做理解题，Claude 口头确认。
- 调重：升级为完成该课 finger exercise / 部分 PS。

> 注：单人自学无法强制（用户可硬点「看过」跳过）；本机制的价值是让 ✅「学会」
> 这一状态**可信**——它必须有用户提交、Claude 审过的证据。

### 模块 C：当前任务提示（P0）
- 显眼卡片：「下一步 → Lec X：主题」，根据打卡进度自动推算。
- 避免「不知道该学啥」的迷茫。

### 模块 D：做作业（P0，核心）
- **题目来源两种**：
  1. 6.100L 现成习题（来自 `problem-sets/`）。
  2. Claude 出的题（Claude 写成文件，工作台读取显示）。
- **题目展示**：标题、描述、要求。
- **代码编辑器**：网页内写 Python。
- **运行**：用 **Pyodide**（浏览器内跑 Python，零安装），点「运行」即时看输出。
- **自动判题（P1）**：题目自带测试用例时，运行后显示「通过 X/Y」。
- **提交**：把答案存到硬盘 `data/submissions/`，供 Claude 读取点评。

### 模块 E：Claude 点评闭环（P0，文件桥接）
- 用户提交后，答案落盘。
- 用户到 Claude Code 终端发起点评（如「点评 ps1」）。
- Claude 读 `submissions/` + 题目，写点评到 `data/reviews/xxx.review.md`。
- 工作台读取并展示点评（手动刷新或轮询）。
- 二期（P2）：接 API，做到网页内一键点评 / 对话。

### 模块 F：学习日志（P1）
- 记录每天「学了啥、卡在哪、心得」，存成结构化文件。
- 替代手动改 `学习路线.md` 里的进度表。

## 5. 技术架构

```
┌─────────────────────────────────────────────┐
│  浏览器（前端 UI）                              │
│  - HTML / CSS / JS                            │
│  - Pyodide：浏览器内运行 Python（做题）          │
└───────────────┬─────────────────────────────┘
                │ HTTP（本地）
┌───────────────▼─────────────────────────────┐
│  本地小服务器 server.py（Python）              │
│  - 端上前端页面                                │
│  - 读课程材料列表（扫 MIT-6.100L/）             │
│  - 读写硬盘上的进度 / 答案 / 日志               │
└───────────────┬─────────────────────────────┘
                │ 读写文件
┌───────────────▼─────────────────────────────┐
│  硬盘上的数据文件（data/）                      │
│  ← Claude Code（本终端）直接读这些文件来点评/出题 │
└─────────────────────────────────────────────┘
```

**关键设计**：工作台本身不内置 AI；它只负责把学习「落到硬盘」。
Claude Code（用户已在用）通过读写这些文件，充当老师。这是 MVP 不接 API 也能闭环的原因。

**技术选型**
- 服务器：Python 标准库 `http.server` 或轻量 Flask（参考 `0-Tools/research-dashboard/server.py` 的现有风格，保持一致）。
- 前端：原生 HTML/CSS/JS（不引入框架，降低小白维护门槛）。
- 运行 Python：Pyodide（CDN 引入，浏览器内执行，零安装）。
- 数据：纯 JSON / 文本文件，人类可读、可被 git 备份、可被 Claude 读。

## 7. 核心工作流

### 7.1 确认学完一课（看过 → 学会）
```
① 用户看完 Lec X，点「👁️ 看过」
② 进入该课「检查点」：做 3-5 题（自动判题 + 理解题）
③ Pyodide 跑自动题 → 即时对错；用户提交检查点作答
   → 写入 data/submissions/lecX.checkpoint.json
④ 用户到终端：「确认我学完 Lec X」
⑤ Claude 读检查点作答 → 自动题全过 + 理解题点头？
   → 写 reviews/lecX.review.md，并把 progress.json 该课标 ✅「学会」(含证据)
   → 没过则指出薄弱点，停留在「看过」，让用户补
⑥ 工作台刷新 → 显示 ✅ 与 Claude 批注；阶段进度条按「学会」数更新
```

### 7.2 做作业 → 点评闭环
```
①（工作台）用户做题，写代码，Pyodide 运行调试
② 点「提交」→ server.py 把答案写入 data/submissions/ps1.py
③ 自动判题（若有测试）→ 显示通过 X/Y
④ 用户到 Claude Code 终端：「点评 ps1」
⑤ Claude 读 assignments/ps1.json + submissions/ps1.py
   → 写 reviews/ps1.review.md（指出问题、给提示、不直接给答案）
⑥ 工作台刷新 → 在题目下方展示 Claude 的点评
⑦ 用户订正 / 进入下一题；进度自动更新
```

> **进度只按 ✅「学会」计**：阶段进度条、当前任务推算都以「学会」为准，
> 「看过」只是中间态。这样进度数字真实反映掌握程度。

## 8. 分期计划

### Phase 1 — MVP（本期）
- 模块 A/B/C/D/E/G（P0）全部。
- 自动判题（D 的 P1）尽量做。
- 目标：跑通两条闭环——
  ①「看课 → 检查点 → 终端确认 → 标记✅学会」
  ②「做题运行 → 提交 → 终端点评 → 看反馈」。

### Phase 2 — 增强
- 网页内直接与 Claude 对话 / 一键点评（接 Claude API）。
- 学习日志模块 F 完整化、数据可视化（学习时长、连续天数等）。
- Claude 根据薄弱点**自动出题**并推送到工作台。

## 9. 验收标准（Phase 1 完成的定义）

- [ ] 敲一句命令能启动，浏览器打开工作台首页。
- [ ] 首页显示五阶段进度条，**按 ✅「学会」数**计算，数字正确。
- [ ] 课程清单有「👁️看过 / ✅学会」两态，点击能打开本地 PDF / 代码。
- [ ] 每节课能进入检查点，做自动判题 + 理解题，提交后落盘。
- [ ] Claude 能读检查点作答，确认通过后该课变 ✅「学会」并记录证据。
- [ ] 当前任务卡片能正确推算「下一步」（以「学会」为准）。
- [ ] 能在网页里写 Python、点运行看到输出（Pyodide 正常）。
- [ ] 能提交作业答案，文件正确落到 `data/submissions/`。
- [ ] Claude 能读到提交、写点评，工作台能显示出来。

## 10. 风险与取舍

| 风险 / 取舍 | 说明 / 应对 |
|------------|------------|
| 每次要敲命令启动 | 接受。顺带练阶段 2 的命令行；可写一个 `启动.command` 双击脚本降低门槛 |
| Pyodide 首次加载慢 | 首次下运行时较慢（几秒到十几秒），之后浏览器缓存；可接受 |
| 点评不是「即时」的 | MVP 靠用户主动来终端找 Claude；二期接 API 做到即时 |
| 进度文件被手滑改坏 | 纯文本可读、可 git 备份；server 写入前做基本校验 |
| 范围膨胀 | 严守「只服务学习 + 小作业」，复杂功能一律推二期 |
