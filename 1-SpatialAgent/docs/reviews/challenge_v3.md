# SpatialAgent 研究计划评审意见 (Reviewer Critique)

作为 AAAI / CHI 级别的评审专家，我认为 **SpatialAgent** 的核心 IDEA（引入建筑学 Space Syntax 理论治疗 LLM Agent 的“空间失明症”）非常吸引人，具备跨学科的深度与极强的论文 Storytelling 潜力。

然而，当前的实验设计和方法论存在几个**致命的逻辑漏洞与评审陷阱**。如果不加修正，很容易在第一轮 Review 中因为“**提示词泄漏 (Data Leakage)**”、“**对比基线不公平 (Unfair Baseline)**”或“**过度硬编码 (Overly Hardcoded)**”等原因被毙掉。

以下是我从最严苛的审稿人角度，对你研究计划的 **6 大核心 Challenge** 及修改建议：

---

### Challenge 1. “这只是一次复杂的提示词工程，存在严重的循环论证”
**【审稿人毒舌】**：
> "作者声称 Agent 产生了对空间的感知并涌现了不同的社交行为。但我发现，在 **4.2 模块**中，作者先通过 Space Syntax 计算出高 Integration，然后转换成自然语言告诉 LLM：*『这是一个人流汇聚的核心区域，是社交活动的中心』*。这不就是相当于直接把答案喂给 LLM，命令它『这里应该社交』吗？LLM 当然会在有这段提示词的时候展现更多社交行为。这根本不是真正的空间感知行为涌现，这是因为你的 Prompt 泄漏了结论和期待！"

**【杀伤力】**：🔴🔴🔴🔴🔴 (极高)
**【应对策略】**：
在“空间→语言”的转换层，**必须降低提示的“引导性 (Directiveness)”**。你不能告诉它“这里是社交中心”或“这对隐私很好”，你只能描述客观物理与拓扑现实：
- **改前（主观暗示）**：视野受限，这意味着较好的隐私，你们的对话不太容易被外人看到。
- **改后（客观陈述）**：该位置被三面实墙包围（连通度=1），视线所及范围不超过正前方2米（视觉深度低）。
你需要证明，仅仅基于**客观结构描述的注入**，基于 LLM 的常识，依然能够导致预期的社会化涌现。

---

### Challenge 2. 基线对比不公平 (Unfair Baseline)
**【审稿人毒舌】**：
> "在 Exp1 中，实验组 (SpatialAgent) 接收到了关于环境非常详尽的描述文本，而对照组 (Baseline) 只是没有『空间感知』模块。这存在明显的信息量不对等。Agent 表现得更好、更真实，可能只是因为喂给 LLM 的 Context Token 变多了（信息更丰富），而不是 Space Syntax 这个理论的功劳。随便一个普通的游戏数值策划手写一段地点环境描述，一样比 Baseline 强。"

**【杀伤力】**：🔴🔴🔴🔴🔴 (极高)
**【应对策略】**：
Exp1 的基线不能只设一个“无空间感知”，必须增加两个**信息量对等的强基线**：
1. **Naive Spatial Baseline**：提供基础位置和手工标签描述（例如：“你在酒馆密室”）。
2. **Rule-based/Random Tag Baseline**：给地点随机或由人类专家手动编写一般性修饰词。
你必须证明：**Space Syntax 动态计算出的拓扑指标**的作用，显著优于那些凭借直觉手工写的“静态文本标签”。

---

### Challenge 3. 规划模块的“硬编码”削弱了大模型的智能
**【审稿人毒舌】**：
> "在 4.4 节（Spatial Planning）中，作者人工定义了一个复杂的空间效用函数 $U = w_1 \times Privacy + w_2 \times Distance + ...$，甚至预设了一张权重表（比如在密谈时 Privacy 权重是 0.5）。既然连意图的权重分布都是作者手工（hardcode）写的标量规则，那么这个大模型在这套系统里到底干了什么？这本质上退化成了经典游戏 AI 的基于效用的系统 (Utility-based AI)，大模型退化成了一个文本输出美化器而已。"

**【杀伤力】**：🔴🔴🔴🔴⚪ (高)
**【应对策略】**：
不要用手工公式算效用决定去哪。你可以**让大模型自己生成权重**或者**让大模型通过评价不同地点的客观 Space Syntax 指标去决定最佳去处**。
具体来说，在 Spatial Planning 里输入全局地点一览（带 Space Syntax 客观参量），让 LLM 自己做 Reasoning 选地点并写出思考链（CoT），这样体现的是大模型本身的规划能力在空间参数下放大，而不是写死算式。

---

### Challenge 4. 20个节点的图太小，“涌现”缺乏说服力
**【审稿人毒舌】**：
> "作者声称验证了空间构型对庞大社会行为的发生有预测作用。但是地图仅仅是一个 20 个节点的抽象文本图？在这么小的、强制交互的模型下得到的『碎片化/中心化社交网络』，基本只是简单图论规律和数学概率在作祟（比如只有一个主路通道，相遇概率原本就是 100%）。这叫数学必然，不叫社会涌现 (Social Emergence)。"

**【杀伤力】**：🔴🔴🔴🔴⚪ (高)
**【应对策略】**：
20 个节点只能用于跑通 Prototype。在最终实验阶段，建议：
1. 将地图扩张到 **50-100 个节点**。
2. **引入现实环境的映射**。比如使用一个著名的建筑平面图（如某经典博物馆布局）或者实际小镇的网格导入（可以从论文《Affordable Generative Agents》用的 Stanford Town 提取纯拓扑），使其更具学术正当性。

---

### Challenge 5. Module 消融实验与指标消融杂糅
**【审稿人毒舌】**：
> "在 Exp3 的消融实验中，我看到作者把去掉了某个具体指标（如 Connectivity）和去掉动态信息放在一起对比。这无法回答一个问题：究竟是你的架构牛逼（比如 Spatial Memory 起到了绝对作用），还是这个 Space Syntax 特定参数牛逼？"

**【杀伤力】**：🔴🔴🔴⚪⚪ (中)
**【应对策略】**：
消融实验需要明确分为两组：
- **Architectural Ablation (架构消融)**：在保持全指标输入的情况下，分别去掉 Memory Retrieval 里的空间相似度权重、去掉 Spatial Action Sampling 检查机制，看哪个模型组件作用最大。
- **Feature Ablation (特征消融)**：在保持完整架构运行的情况下，逐一移除 Integration、Visual Depth 等输入提示，看哪个建筑学指标最关键。

---

### Challenge 6. The "So What" Question（杀鸡焉用牛刀？）
**【审稿人毒舌】**：
> "对于一个 RPG 游戏里 10 个人物和二十几个房子而言，任何一个有经验的关卡设计师都能手工把寻路热区和私密区划分出来，为什么非要花巨大精力使用复杂的 Space Syntax 计算跑拓扑分析？你的实际应用场景在哪？"

**【杀伤力】**：🔴🔴🔴⚪⚪ (中)
**【应对策略】**：
你必须在 Motivation / Discussion 中强烈说明：你的方法并非为了给一两个手工固定小副本打标签使用，而是**提供一种自动化应对动态/超大/程序生成的环境的能力**。
例如：对于 Procedural Content Generation (PCG) 随机生成的地牢、大逃杀游戏的巨型地图场景演化、甚至是机器人遇到真实的未知环境，人类无法做预先手工打标，此时只有算法通过实时计算 Space Syntax 后传给 Agent，才是实现群体 AI 智能化感知的唯一泛化方案。

---

### 🌟 给作者的最终建议行动指南 (Actionable Steps)：
1. 改写 4.2 节的空间转换提示规则，让转化出来的 Prompt 完全呈中性、客观。
2. 用大模型的 CoT 推理或者软权重，替换 4.4 节里硬编码的算式，让系统 AI 的原味更浓。
3. 增加与“手工静态标签 Agent”之间的公平对比。
4. 在撰写论文的 Introduction 时，一定要拿 **Procedural Generation（程序化生成的大型动态环境）** 作为采用该方法核心不可替代的场景去背书。
