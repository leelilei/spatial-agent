# SpatialAgent Research Plan v6 审稿式评审总结

> 评审对象：`../plans/plan_v6.md`
> 评审身份：AAMAS / AAAI 匿名审稿人
> 评审标准：顶会投稿级方法论文蓝图

---

## 总体判断

`v6` 是目前为止最接近“可投稿版本”的研究计划。与 `v5` 相比，它真正解决了三件此前最关键的问题：

- 把 `C6 - C2` 升格为主比较，修复了“空间结构信息 vs 一般上下文增强”比较不干净的问题
- 把 run-level 主模型改成 `matched-seed` 设计下的 `DV ~ condition + (1|seed)`
- 把角色异质性分析从 run-level 错位地移到了 `agent × seed` 层级

这三点都不是表面修饰，而是实质性的识别强化。也正因为如此，`v6` 的剩余问题已经从“根本性漏洞”降到了“最后几处统计与操作化收口”。

我的总体结论是：

- 作为研究计划：**Accept**
- 作为投稿级方法蓝图：**Weak Accept / Borderline Accept**

如果继续修改，我不建议再扩内容；我建议只做最后一轮局部收口，把已经成型的主证据链做得更锋利。

## 主要问题

## P0-1. `TAR_run` 的统计操作化仍然不够明确，存在“理论上正确、实现上模糊”的问题

`v6` 最重要的进步之一是把 `TAR` 从高/低节点差值提升为**连续型主实现**。方向上这是对的，我支持保留。

但当前文档仍没有把下面这件事写清楚：

> **一个具体的 `TAR_H1_run` 或 `TAR_H2_run` 到底是如何从单个 run 中计算出来的？**

你现在写的是：

```text
H1: sociality ~ standardized Integration
H2: privacy_behavior ~ standardized MeanDepth
H3: gatekeeping ~ standardized Control
```

然后又说 run-level 主验证模型是：

```text
DV_run ~ condition + (1|seed)
```

这意味着：

- 每个 run 必须先产出一个标量 `TAR_H1_run`
- 再把这个标量作为 run-level DV 拿去做条件比较

但文档里没有明确这个标量是如何估出来的。可能的实现至少有三种，而它们统计含义并不一样：

1. **在每个 run 内单独拟合一个回归系数**，把该系数当作 `TAR_run`
2. **按高/低分位或 top/bottom 节点做差值**，再当作 `TAR_run`
3. **先做 event-level 混合模型，再把模型系数投影成 run-level summary**

### 为什么这是严重问题

因为这不是“写作没展开”的小问题，而是会直接影响：

- 主因变量的可重复性
- 功效估计的合理性
- `TAR` 是否比 `BSR` 更噪

尤其在 20 节点小图上，如果你对每个 run 单独拟合回归系数：

- 自变量取值范围有限
- 事件数量虽多，但行为类别可能稀疏
- 某些 run 中的极端节点访问次数可能不足

那么 `TAR_run` 本身就可能非常不稳定。

### 建议

在 `v6` 中把 `TAR_run` 的生成过程写成一个明确协议。最稳的写法是：

#### 主方案：预定义 summary slope

对每个 run：

1. 先把所有行为事件按节点空间指标汇总到 location-level
2. 计算 location-level 的平均 sociality / privacy / gatekeeping rate
3. 在该 run 内做：

```text
location_behavior_rate ~ standardized_spatial_feature
```

4. 回归系数即为 `TAR_run`

这样会比直接在 event-level 上对每个 run 拟合二元行为模型更稳定。

#### 辅助方案：分位差值图示

保留 top/bottom 25% 节点差值，只作为图示，不作为主验证统计量。

一句话说，`v6` 已经把 `TAR` 的概念做对了，但还需要把**每个 run 如何生成一个稳定的 TAR 值**写得像 protocol，而不是像定义。

## P0-2. `Exp1C` 的因子解释仍然存在“把 H1 与 H2 混成一个轴”的风险

`v6` 比 `v5` 更强的一点，是你已经为 `Exp1C` 加了 lexical norming，并清楚区分：

- `topology` 主效应
- `semantic label` 主效应
- 交互效应

但目前这个 2×2 设计仍有一个残余问题：

你把行因子写成了：

- 高拓扑中心性
- 低拓扑中心性 / 高深度

这其实不是一个干净的一维因子，而是把两种结构含义打包在一起了：

- `高 Integration`
- `高 MeanDepth`

这会让解释变得有些含混：

- 如果你在“低拓扑 / 高深度”这一侧看到了更私密行为
- 到底是因为“低拓扑”
- 还是因为“高深度”
- 还是因为两者一起形成了更强的私密语义？

### 为什么这是问题

`RQ4` 的目标是区分：

- 结构性空间效应
- 语义常识效应

但当前的结构性因子本身就不是单一维度，因此你最终区分的更像是：

> “一组公共结构信号” vs “一组私密结构信号”

这当然仍有价值，但不再是一个干净的单因子解释。

### 建议

有两种更稳的改法：

#### 方案 A：明确把 `Exp1C` 改名为“public-structural vs private-structural composite factor”

也就是承认这里操控的不是单一拓扑维度，而是一组复合结构语义。

#### 方案 B：拆成两个更小的探索性实验

1. `Integration × SemanticLabel`
2. `MeanDepth × SemanticLabel`

从投稿可执行性看，我更推荐 **方案 A**。因为它不需要扩实验，只需要更诚实地改写解释口径。

当前写法最危险的地方不在于实验不能做，而在于：

> 它容易让读者以为“topology”是一个单一可解释的轴，但实际上你操控的是两个不同方向的结构特征。

## P1-3. Confirmatory claim 的统计边界虽然更诚实了，但仍需要在摘要级叙述中再降半档

`v6` 已经非常诚实地承认：

- `30 matched seeds / cell`
- run-level 可检测效应约为 `d >= 0.74`

这比 `v5` 更好，但从顶会审稿人的角度，这仍意味着：

> 你的验证性分析主要能识别中到大效应，而不是一般意义上的“只要存在效应就能确认”。

这本身不是问题，问题在于论文的若干表述仍然可能让人期待更强的确认力。例如：

- “结构化空间表征能否稳定改变 LLM Agent 行为”
- “完整空间化架构相对 Topology-Only 是否带来显著增量”

这些句子本身没有错，但如果放进摘要、贡献或标题附近，容易被读者默认理解为：

> 这是一次足够有力的确认性检验

### 建议

在论文级表述中，把主验证结论进一步限制为：

- `tests for robust / practically meaningful effects`
- `tests whether large, architecture-level effects are detectable under controlled settings`

如果你愿意再稳一点，甚至可以在引言中主动加一句：

> 由于资源约束，本研究的 run-level 验证性分析旨在检测中到大效应，而非排除所有中小效应。

这会显著降低审稿人对 negative result 的误读风险。

## P1-4. `C2` 现在已经更合理，但仍需补一句“为什么它不是纯 token-length control”

这是个不大但值得补的点。

你已经把 `C2` 精确定义为：

> stable non-spatial affordance baseline

我认为这是正确的改法。但文中还可以再前置一句：

> 我们不再把 `C2` 定义为纯信息量控制条件，而是把它定义为“稳定、可行动、但与空间结构解耦的替代性地点 affordance”。

因为现在的 `C2` 已经明显不是：

- 纯长度匹配
- 纯噪声条件

而是一种很强的竞争基线。把这一点说透，反而会增强你的方法论说服力。

## 主要优点

### 1. 阶段2主比较链现在终于是逻辑自洽的

这是 `v6` 最大的改进。`C6-C2` 取代 `C4-C2` 后，空间表征效应、采样效应和总系统效应终于被拆开了。

### 2. Matched-seed 设计非常加分

这是一个投入小、回报大的方法优化。它让阶段2从“有重复的比较”升级为“真正受控的 blocked comparison”。

### 3. Run-level / agent×seed / event-level 三层分析结构比前几版成熟得多

现在你终于把：

- 主验证
- 异质性分析
- 机制探测

放在了不同层级里，这会让论文结果部分清楚很多。

### 4. `TAR` 的双轨实现是正确方向

连续型主实现 + 高低分组图示，这是比 `v5` 更稳的选择。

### 5. 整体主张边界控制得很好

`v6` 已经很少出现“设计只能支撑 A，但文字像在暗示 B”的问题。相比前几版，这一点进步很大。

## 三条最高优先级修改建议

### 1. 把 `TAR_run` 的生成过程写成一个明确 protocol

说明每个 run 如何从 location-level 或 event-level 数据稳健地产生一个标量 TAR，用于主验证模型。

### 2. 重新命名或重述 `Exp1C` 的“topology”因子

避免把 `高 Integration` 与 `高 Depth` 混成一个看似单一的拓扑轴。更诚实的写法会更稳。

### 3. 在摘要级写法中进一步强调“run-level 主要检测中到大效应”

不是因为你的设计不够好，而是因为你已经足够诚实，最好把这份诚实贯彻到底。

---

## 结语

`v6` 已经从“研究计划”非常明显地走向了“可投稿方法蓝图”。它最难得的地方在于：你没有继续通过增加实验来制造一种“看起来更完整”的错觉，而是在持续做真正提升可辩护性的事情：

- 收紧主比较
- 收紧统计层级
- 收紧主张边界

现在剩下的问题都非常集中，而且都属于可修复的问题，而不是换题级问题。

**一句话总结：`v6` 已经接近投稿状态，下一步最值得做的不是再扩设计，而是把 `TAR` 的计算 protocol 和 `Exp1C` 的因子解释彻底写实。**
