# SpatialAgent Research Plan v5 审稿式评审总结

> 评审对象：`../plans/plan_v5.md`
> 评审身份：AAMAS / AAAI 匿名审稿人
> 评审立场：严格但建设性，关注理论主张是否与实验识别严格对齐

---

## 总体评价

`v5` 是目前最成熟的一版，已经明显具备了“可投稿方法蓝图”的形状。相比 `v4`，这版最大的进步不是再加新实验，而是**终于开始把论文写作逻辑压缩成主证据链**：

- 用 `BSR + TAR` 区分“有无空间响应”与“是否按理论方向响应”
- 把阶段2压缩成 4 个验证性核心条件
- 把 `C2` 改成 run 内稳定、run 间随机的非空间基线
- 把 `Exp1C` 的语义标签问题前移到 lexical norming
- 把阶段3进一步降为可选扩展

从研究计划角度，我会给出：**Strong Weak Accept**。  
从投稿级方法蓝图角度，我的结论是：**Borderline Accept，接近可投，但还存在几个必须在实现前澄清的关键识别问题。**

最值得肯定的是：`v5` 的问题已经不再是“故事太大”，而是“最后几个统计和对照定义还不够严丝合缝”。这说明计划已经进入了最后一轮方法学打磨区间。

---

## 主要问题（按严重程度排序）

## P0-1. `C4 vs C2` 仍然不是一个干净的“空间结构信息 vs 一般上下文增强”比较

这是我认为 `v5` 当前最重要的问题。

你在阶段2的主比较链中写道：

```text
C4 - C2 = 结构化空间信息 vs 一般非空间上下文
```

但事实上：

- `C4 Full SpatialAgent` 包含 `Perception + Action Sampling`
- `C2 Stable Rich Non-Spatial` 不包含 `Action Sampling`

因此，`C4 > C2` 的差异同时混合了两件事：

1. 空间结构化信息是否优于非空间上下文
2. `Action Sampling` 模块本身是否带来增益

也就是说，这个对比**不能单独支持“空间结构信息优于一般上下文增强”**这一解释。

### 为什么这是严重问题

因为 `v5` 的一个核心论文卖点正是：

> 这种效果不是“多给一点上下文”就能得到的

但在当前设计下，真正更公平的比较其实应该是：

- `C6 Perception-Only` vs `C2 Stable Rich Non-Spatial`

因为这两个条件都没有 `Sampling`，差异更接近“空间结构信息 vs 非空间上下文”的内容效应。

### 建议

把阶段2的主比较链重写为：

```text
C4 - C1 = 完整空间化架构增量效应
C6 - C1 = 空间表征本身的增量效应
C4 - C6 = Action Sampling 的增量效应
C6 - C2 = 空间结构信息 vs 非空间上下文
```

而不是把 `C4 - C2` 直接当作结构信息与一般上下文的对照。

如果你坚持保留 `C4 - C2`，那它在正文中只能被解释为：

> 完整空间化架构相对于稳定非空间上下文条件的总增益

而不能更窄地解释为“空间结构信息本身更优”。

## P0-2. Run-Level 模型的统计写法目前不自洽

你在 `7.2` 中将 run-level 分析定义为：

> 每个 run 汇总成一个数据点

但紧接着给出的模型是：

```text
TAR_H1 ~ condition + social_tendency + (1|run_id)
TAR_H2 ~ condition + social_tendency + (1|run_id)
entropy ~ condition + social_tendency + (1|run_id)
```

这在统计上存在两个明显问题：

### 问题1：`(1|run_id)` 不成立

如果每个 `run` 已经被汇总为一个观测点，那么 `run_id` 没有重复观测，不能再作为随机效应使用。此时：

- 要么是普通线性模型 / 广义线性模型
- 要么你需要一个更高层级的分组变量，比如 `seed`、`map_variant`、`batch`

否则这个随机项是没有意义的。

### 问题2：`social_tendency` 在 run-level 上定义不清

如果每个 run 的 10 个 NPC 角色组成是固定平衡的，那么 run-level 聚合后：

- `social_tendency` 不是一个随 run 变化的协变量
- 它不能作为 run-level 固定效应直接进入模型

除非你改成：

- agent-level 聚合
- 或 event-level 模型

否则这个变量层级与 DV 层级不一致。

### 为什么这是严重问题

因为你现在最想强调的一个优点，就是：

> run-level 验证性分析更干净、更保守

但如果 run-level 模型的层级定义本身不严谨，审稿人会立刻质疑：

- 你是否真的理清了独立样本单位
- 你是否只是在把 mixed-effects 作为一个“看起来高级”的写法

### 建议

把 run-level 主分析改成以下两种之一：

#### 方案 A：真正的 run-level 线性模型

```text
DV_run ~ condition
```

如果你有 matched seeds，则可写为：

```text
DV_run ~ condition + (1|seed)
```

#### 方案 B：agent-level 聚合模型

让每个 run × agent 成为一个数据点：

```text
DV_agent_run ~ condition + social_tendency + (1|run_id) + (1|agent_id)
```

这样 `social_tendency` 才是有定义的，随机效应也成立。

在当前版本里，建议你**不要同时追求“run-level 很干净”与“保留角色协变量”**。这两件事现在写在一起，反而破坏了清晰度。

## P1-3. 缺少 matched-seed / blocked design，会浪费你来之不易的 run-level 功效

`v5` 最大的资源投入是把阶段2核心条件提升到 `30 runs / cell`。这是非常正确的方向。

但现在还有一个明显可以进一步增效、却没有写进设计的地方：

> 不同条件之间是否共享同一组随机种子和初始世界实例？

目前文档里只写了：

- NPC 位置随机化
- `C2` 描述 run 间随机
- 多 runs 重复

但没有写明是否采用**配对式随机种子设计**，即：

- 对于同一个 `seed_k`
- 在 `C1 / C2 / C4 / C6` 下使用同样的初始 NPC 位置配置、同样的随机事件时序、同样的环境初始状态

### 为什么这很重要

如果不做 matched-seed：

- 条件差异会和 run 本身的随机波动混在一起
- 你需要更多 runs 才能稳定估计效应

如果做 matched-seed：

- 你可以把条件比较变成更接近配对比较
- 显著降低 run-level 方差
- 对你这种资源紧、主效应可能只是中等偏大的设计尤其有价值

### 建议

在阶段2主实验中明确采用：

```text
for seed in 1..30:
  固定 NPC 初始位置分配
  固定环境随机事件序列
  固定 C2 描述池分配表
  在 C1/C2/C4/C6 下分别运行
```

然后主分析用：

```text
DV ~ condition + (1|seed)
```

这会比现在的纯独立 runs 更强，也更容易说服审稿人。

## P1-4. `TAR` 的思想是对的，但高/低分组法仍可能让 20 节点小图上的估计过于脆弱

`TAR` 是 `v5` 的一个真正进步，因为它把理论方向性明确引入了主结果。但你当前的定义仍然主要基于：

- 高 vs 低 `Integration`
- 高 vs 低 `Depth`
- 高 vs 低 `Control`

在 20 节点图里，这会带来两个风险：

1. 高/低分组对 cut-off 很敏感  
2. 某些指标的极端节点数可能太少，导致 `TAR` 在 run-level 上噪声很大

这对 `H3` 尤其明显，因为你自己已经承认高 `Control` 节点可能很少。

### 建议

把 `TAR` 的正式实现写成“双轨”：

#### 主实现：连续型

```text
behavior ~ standardized_spatial_feature
TAR = 该连续特征的方向性回归系数
```

#### 辅助实现：高/低分组

用于可视化展示和直觉解释。

这样你既保留了论文可读性，也避免把主验证建立在脆弱的二分法上。

如果不这么做，审稿人很容易问：

> 你的 TAR 结果是否只是某个分组阈值的产物？

## P2-5. `C2` 虽然已经明显改善，但仍需进一步说明“稳定非空间语境”是否会形成替代性的地点语义

`v5` 把 `C2` 从“每轮随机噪声”改成了“每个 run 内位置稳定、run 间随机”，这是比 `v4` 更合理的。

但剩下的一个小问题是：

> 如果同一位置在整个 run 内持续携带某种稳定的非空间描述，这个位置本身就会获得一种替代性的“地点语义”。

例如：

- 某个节点在整个 run 中始终对应“面包香气、轻声哼歌”
- Agent 可能把它当成“舒适、温暖、适合放松的地方”

这当然仍然是合法的强基线，但它不再只是“额外上下文”，而更像是：

> 一种稳定的、非空间的地点 affordance 设计

### 建议

在论文中明确承认这一点，并把 `C2` 更准确地描述为：

> stable non-spatial affordance baseline

而不是更宽泛的 `rich non-spatial context`

这样概念会更精确，也能减少审稿人对 `C2` 定义滑动的质疑。

## 主要优点

### 1. `v5` 首次真正把“理论方向性”放进主结果结构

`BSR + TAR` 的双主因变量设计，是目前整个计划最值得保留的部分之一。它把“有无效应”和“效应方向是否支持理论”拆开，这是此前几版都没真正做到的。

### 2. 阶段2的资源集中化非常正确

与其在 8 个条件上都做半强不弱的验证，不如把资源集中到 4 个最关键条件上。这个决定显著提高了计划的投稿可行性。

### 3. NPC 随机化和阶段3降级都很成熟

这说明作者已经不再把叙事完整性置于识别之上，也不再让阶段3绑架整个项目。这是明显的研究成熟信号。

### 4. `Exp1C` 的 lexical norming 是重要补丁

这使得 `RQ4` 从“有意思的冲突提示词实验”进一步接近“有定义的因子设计”。

### 5. 主张边界控制得更好了

`v5` 在语气上比前几版稳健得多，已经开始像一篇会被认真对待的方法论文，而不是一个想一口气验证太多理论的大项目。

## 三条最高优先级修改建议

### 1. 把 `C6 - C2` 升格为阶段2主比较之一

这是目前最干净的“空间结构信息 vs 非空间上下文”比较。不要再让 `C4 - C2` 承担这个结论。

### 2. 重写 run-level 主分析模型

如果每个 run 只有一个数据点，就不要再写 `(1|run_id)`；如果你想保留角色协变量，就把聚合层级下放到 `agent × run`。

### 3. 在阶段2显式采用 matched-seed 设计

这是你在不显著增加成本的情况下，最能提升验证性证据质量的一步。

---

## 结语

`v5` 已经明显进入“可以认真准备实现和投稿”的阶段。它最大的优点，不是实验越来越多，而是终于开始把：

- 什么是主证据
- 什么是机制补充
- 什么是探索性扩展

这三件事区分开了。

当前剩余的问题也非常集中，基本都不是“换题”级别的问题，而是“最后一轮统计与对照定义收口”的问题。这是好消息。

**一句话总结：`v5` 已经很接近投稿状态，下一步最该做的不是再加内容，而是把阶段2的主比较定义和 run-level 统计模型彻底修正到无可挑剔。**
