# CityAgency Results Ledger

This file is the canonical experiment ledger for `6-city`, following the same
role as `5-Telephone/RESULTS.md`.

Raw and derived experiment outputs live under:

```text
6-city/results/
```

Human-readable experiment notes live under:

```text
6-city/docs/experiments/
```

## Archive Standard

Each repeated experiment directory should contain:

- `run_config.json`: command-level configuration and timestamp
- `runs.json`: one row per repeat with trace/judge artifact locations
- `manifest.json`: metrics, scenario/agent set, row count, and run records
- `repeated_summary.md`: paper-facing table
- `all_runs.csv`: one row per repeat/scenario/agent
- `agent_repeated_summary.csv`: agent-level mean/std table
- `scenario_agent_repeated_summary.csv`: scenario-agent diagnostics
- `failure_taxonomy_summary.csv`: aggregated failure counts
- `repeat_XX/traces/`: first-pass city trace outputs
- `repeat_XX/judged/`: second-pass plausibility judge outputs

Single-run or smoke experiments should still keep:

- the exact command in a `docs/experiments/*.md` note
- result tables under `6-city/results/`
- enough raw JSON/CSV artifacts to rerun the analysis

## Next Pending Result

The project now has two explicitly separate tracks. The v1.0-rc1 paper study
remains frozen evidence; v1.1 is a new benchmark-construction programme and
must not inherit the word "benchmark" merely from having more generated data.

### v1.1 benchmark construction

Wave-4's offline construction passed every gate, but its **public six-system
calibration (144 traces) failed promotion: 1 of 8 templates accepted**. The wave
is too easy for the three calibration models — system mean 0.87 against Wave-3's
0.58, with roughly half the system spread — which destabilises corrected
item-total correlation. Two mechanisms (`memory_conditioned_preference`,
`resource_budget_allocation`) are hard ceilings because their intentions state
the answer. The registry therefore stays at 24 templates / 72 public instances,
and the public construction gap is **not** closed. Next step is mechanism
hardening followed by re-calibration, which needs fresh authorization.

The immediate task is controlled mechanism expansion from the eight templates
stable across all three public worlds (24 calibrated instances) toward the
144-item target. New candidates must add genuinely different mechanisms, not
only rename locations or clone parameters. Each generated variant must independently
pass oracle and matched-negative gates, six-system difficulty calibration,
range and corrected item-total thresholds, and leakage/provenance audits.
The registry now contains 16 stable three-world templates and 48 calibrated
public instances: two independent mechanisms per construct. Wave-3 and Wave-4
must add two more mechanisms per construct before the planned 12-public-item
cells are complete. The release accepted count stays zero until expanded
variants, split assignment, private transfer, and release-level gates pass.
