# 实验目的

验证 WikiChurches 专家选择的构件框，是否比同一图像中面积和长宽比匹配的
随机区域携带更多建筑风格判别信息。

这是在实现 positive-only token adapter 前的停止性探针。若不能超过随机
区域，则终止整个“局部构件改善分类”方向。

# 预设协议

- 只编码官方 train+val 中带构件框的图像；
- 将 test 文件名作为排除集合，test 图像编码数必须为 0；
- 每个官方框生成 8 个同图、同面积、同长宽比的随机控制区域；
- 官方框与控制框均增加 15% context，再通过 frozen CLIP ViT-B/16 编码；
- 主要统计单位为 church-disjoint 图像，不按框数加权；
- style margin 使用四个建筑风格文本原型；
- 10,000 次图像级配对 bootstrap；
- 4-fold × 20-repeat church-disjoint prototype CV。

GO 必须同时满足：

1. 图像级平均配对 margin 大于 0；
2. bootstrap 95% CI 下界大于 0；
3. 至少 3/4 风格方向为正；
4. 官方框 prototype balanced accuracy 比随机区域至少高 2pp。

# 结果

| 指标 | 结果 |
|---|---:|
| 图像 / church | 97 / 97 |
| 官方框 | 433 |
| 随机控制 | 3,464 |
| 编码 test 图像 | 0 |
| 图像级 style-margin 配对差 | +0.00649 |
| 配对 bootstrap 95% CI | +0.00511–+0.00803 |
| 正向风格 | 3/4 |
| 官方框 prototype balanced accuracy | 73.43% |
| 随机区域 prototype balanced accuracy | 49.22% |
| Prototype 配对差 | +24.21pp |

分风格：

- Romanesque：`+0.00797`；
- Gothic：`+0.00740`；
- Renaissance：`−0.00026`；
- Baroque：`+0.00413`。

四项预设检查全部通过，判定为 **GO**。
Prototype CV 的 20 个重复全部为正，重复级差值范围为
`+18.62–+31.74pp`，不是由单次 fold 划分驱动。

# 完整性与敏感性

- 正式进程退出码：0；
- 无 OOM、无 traceback；
- 3,464 个随机控制中有 16 个（0.46%）超过 0.05 官方框重叠阈值；
- 16 个控制全部来自两个超大官方框；
- 事后排除这两个框，图像级配对差为 `+0.00648`，
  bootstrap 95% CI 为 `+0.00509–+0.00803`，结论不变。

# 解释边界

本实验支持：

> 专家选择的构件框确实包含超出匹配随机区域的建筑风格信息。

本实验不支持：

- 框外区域是真负例；
- 原始标注一定存在漏标；
- positive-only adapter 已能提高最终 few-shot 分类；
- Renaissance 上已获得稳定区域增益。

# 下一步

可以进入 positive-only box-anchor token adapter 的最小实现：

1. Tip-Adapter-F 作为全局主干；
2. dense token / region crop 作为局部分支；

4. 框外 token 不进入负损失；
5. validation-only 选择融合门控，再用新 seed 冻结确认。
