# 目的

PartImageNet 的三次 Oracle 门均失败后，本实验不再继续调原机制，而是在最接近
先例 Privileged Pooling 使用的 CUB 数据上，先复现“部件特权监督具有正向下游
上限”这一必要条件。

# 冻结边界

- CaltechDATA 官方包：1,150,585,339 bytes；
- MD5：`97eceeb196236b17998738112f37df78`，校验通过；
- 只使用官方 train；
- 200 类 × 每类 10 张，共 2,000 张；
- 五折，每折 400 张 OOF；
- Global 与 Full-Keypoint Oracle 使用相同 ResNet-50 `layer4` 适配预算；
- 门槛：Oracle 总体 OOF BA 相对 Global 至少 +2pp；
- 官方 test 图像读取/编码数为 0。

# 结果

| Fold | Global | Full-Keypoint Oracle | Delta |
|---:|---:|---:|---:|
| 0 | 65.75% | 70.50% | +4.75pp |
| 1 | 67.25% | 70.75% | +3.50pp |
| 2 | 65.50% | 72.25% | +6.75pp |
| 3 | 66.00% | 71.50% | +5.50pp |
| 4 | 62.75% | 69.75% | +7.00pp |
| **OOF** | **65.45%** | **70.95%** | **+5.50pp** |

五折全部为正，整体超过预注册门槛。判定 Go。

# 安全性观察

平均增益并不均匀：97 类提高、57 类不变、46 类下降，最差类别为 −40pp。
由于每类只有 10 个 OOF 预测，类别差以 10pp 为步长，不能把最差值当成稳定
总体风险估计；但必须保留类别级伤害作为下一阶段的核心终点。

# 裁决

CUB 上已建立足够正 Oracle 上界，允许冻结该机制并进入选择性缺失诊断：
MCAR/MAR/MNAR/support-isolation。当前仍没有纠偏方法结果，不能声称“安全迁移
已解决”，也不打开官方 test。
