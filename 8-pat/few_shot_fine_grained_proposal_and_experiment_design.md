## 1. 研究概述

本研究面向少样本细粒度视觉语言识别，关注一个潜在但尚未被充分验证的问题：

> 当局部判别区域标注不完整时，传统区域—文本训练可能会把未被标注、但实际仍具有类别判别价值的区域错误地当作负样本，从而形成假负监督，并进一步损害少样本分类性能。

本研究拟将：

- 已标注区域视为可靠正例；
- 未标注区域视为正例与负例的混合集合；
- 通过高可信正例扩展学习区域—语义对应关系；
- 用该区域语义关系校准 Few-shot VLM 中的 Patch 节点筛选；
- 最终将局部判别知识蒸馏到轻量 Few-shot Adapter 中。

主实验场景拟采用建筑风格识别数据集 WikiChurches，并使用 CUB-200-2011 等通用细粒度数据集验证方法的可迁移性与通用性。

## 2. 论文定位

本论文首先是一篇**少样本细粒度模式识别方法论文**，其次才是一篇建筑相关论文。

不应将研究表述为：

> 使用 CLIP 或 TOGA 进行建筑风格分类。

而应表述为：

> 研究不完整局部判别标注条件下，视觉语言模型如何避免错误负监督，并提升少样本细粒度识别性能。

建筑风格识别的价值在于，它同时具备以下困难：

- 类间差异细微；
- 类内差异较大；
- 判别信息常集中于局部建筑构件；
- 拍摄角度、光照与背景变化明显；
- 局部专家标注数量有限且可能不完整。

## 4. 研究背景

细粒度识别通常依赖局部判别证据。

| 领域 | 典型局部判别证据 |
|---|---|
| 鸟类 | 喙、头部、翅膀、羽毛纹理 |
| 汽车 | 车灯、格栅、轮毂、车尾 |
| 飞机 | 机翼、发动机、尾翼 |
| 建筑 | 拱券、扶壁、窗饰、柱式、屋顶 |

在 Few-shot 场景中，模型容易面临：

1. 支持样本数量过少；
2. 支持图像存在视角与背景偏差；
3. 模型依赖统计上相关但语义上错误的区域；
4. 局部专家标注无法覆盖全部图像；
5. 未标区域可能被错误地用作负监督。

现有部件监督方法通常默认：

- 标注体系较完整；
- 每张图像具有固定部件集合；
- 未标区域可作为背景或负例。

但真实建筑数据中的局部专家标注可能仅强调少数具有代表性的风格特征，而不一定穷尽所有相关构件。

## 5. 核心研究问题

### 5.1 当前研究假设

> WikiChurches 中的局部构件框可能属于代表性、非穷尽式标注。框外区域中可能仍包含未被标出的有效判别构件。

例如，一张 Gothic 建筑图像只标注了一个 pointed arch，但图中仍可能存在：

- 其他尖拱；
- 飞扶壁；
- 窗饰；
- 尖塔；
- 肋拱相关结构。

若普通区域—文本训练采用：

- 框内 Patch 为正样本；
- 框外 Patch 为负样本；

则可能错误压低未标正例与相应属性文本之间的相似度。

### 5.2 真正需要解决的问题

本研究并非一般的：

> 如何利用局部构件框？

而是：

> 如何在局部判别区域标注不完整的情况下，学习可靠的区域—语义关系，并避免假负监督影响少样本分类？

## 8. 候选方法设计

> 本节为候选方案。只有在问题验证与专项查重通过后，才能正式确定。

### 8.1 正例—未标注区域建模

对于局部属性 \(a\)，定义：

\[
P_a=\{\text{位于已标注框内的正例 Patch}\}
\]

\[
U_a=\{\text{位于已标注框外的未标注 Patch}\}
\]

其中，未标注集合 \(U_a\) 可能包含：

- 真负例；
- 未被标出的正例。

因此，不能直接将 \(U_a\) 全部作为负样本。

### 8.2 高可信正例扩展

对未标注 Patch \(z_j\) 计算与属性文本 \(t_a\) 的匹配分数：

\[
q_{j,a}=\operatorname{sim}(z_j,t_a)
\]

但不能只依据单次相似度阈值扩展正例，还需考虑：

- 多视图增强一致性；
- 同类别支持样本一致性；
- 与易混淆类别属性的对比可分性；
- 模型预测不确定性；
- 不同尺度 Patch 的一致性。

只有高可信 Patch 才加入正例集合。

其余 Patch 继续保持未标注状态，不被强制归类为负样本，也不要求生成完整伪标签。

### 8.3 Patch 节点校准

设母体方法原始 Patch 判别分数为：

\[
d_j
\]

不完整标注学习得到的区域语义分数为：

\[
q_j
\]

候选校准形式包括：

\[
w_j=d_j+\lambda q_j
\]

或：

\[
w_j=\sigma(g(d_j,q_j,u_j))
\]

其中：

- \(u_j\) 表示区域预测不确定性；
- \(g(\cdot)\) 表示轻量门控模块；
- \(w_j\) 用于调整 Patch 节点在图教师中的权重。

### 8.4 知识蒸馏

校准后的图教师继续按照母体框架，将局部语义知识蒸馏到轻量 Few-shot Adapter。

推理阶段不需要：

- 局部构件框；
- 区域监督分支；
- PU 分支；
- 图教师；
- 额外图推理。

需要明确：

> 蒸馏与训练期图教师不是本研究创新；本研究的候选增量仅在于不完整区域监督建模及其对 Patch 筛选的校准作用。

## 12. 阶段一：标注协议确认

### 12.1 核心问题

需要确认：

> 数据集专家是否被要求穷尽标注图片中的全部相关构件，还是只标注具有代表性、清晰可见的构件？

建议向数据集作者询问：

> In the bounding-box annotation process, were experts instructed to exhaustively annotate every occurrence of each characteristic structure, or only to highlight representative and clearly visible examples? Should regions outside annotated boxes be treated as confirmed negatives or simply as unlabeled regions?

### 12.2 判断标准

- 若作者确认标注是代表性、非穷尽式，则 PU 问题前提成立；
- 若作者确认标注要求尽量穷尽，则需重新审视该方向；
- 若无法获得作者回复，则必须依靠标注审计与图像实例分析建立证据。

## 13. 阶段一：漏标审计

### 13.1 审计规模

建议抽取：

- 40–60 张带构件框的 WikiChurches 图像；
- 覆盖四种建筑风格；
- 覆盖高频构件类型；
- 尽量包含不同视角、远近与遮挡程度。

### 13.2 建议审计构件

包括但不限于：

- pointed arch；
- round arch；
- tracery；
- buttress；
- pinnacle；
- pilaster；
- rose window；
- dome；
- column order；
- decorative facade elements。

### 13.3 标注方式

建议至少由两名具备建筑背景的标注者进行较完整复核。

需要记录：

- 原始框；
- 新增确认的构件；
- 不确定构件；
- 构件类别；
- 构件尺寸；
- 构件遮挡程度；
- 是否重复出现；
- 标注者一致性。

### 13.4 主要统计指标

#### 漏标正例比例

\[
\text{Missing Positive Rate}
=
\frac{\text{新增确认的未标构件数量}}
{\text{重新确认的全部构件数量}}
\]

#### 原始构件标注召回率

\[
\text{Original Annotation Recall}
=
\frac{\text{原始正确构件数量}}
{\text{重新确认的全部构件数量}}
\]

同时统计：

- 不同风格的漏标比例；
- 不同构件的漏标比例；
- 小目标与大目标的漏标差异；
- 遮挡程度与漏标率关系；
- 标注者一致性；
- 框外高相似 Patch 中真实正例比例。

### 13.5 阶段通过标准

不设置绝对硬阈值，但至少应满足：

- 漏标现象具有稳定性，而非极少数案例；
- 多个类别与多个构件上均可观察；
- 两名标注者对新增构件具有较高一致性；
- 漏标具有可解释规律。

## 14. 阶段一：诊断实验

在设计复杂网络前，先完成最小诊断实验。

### 14.1 对比方案

| 方法 | 框外区域处理 |
|---|---|
| PN Baseline | 框外 Patch 全部作为负样本 |
| Ignore Baseline | 框外 Patch 不参与区域损失 |
| Existing PU | 使用已有正例—未标注风险估计 |
| Pseudo-label | 高置信 Patch 生成伪正例 |
| Oracle | 使用人工补全后的局部标注 |

### 14.2 评价指标

局部任务：

- Region Recall；
- Region Precision；
- 区域—文本匹配准确率；
- Pointing Game；
- 定位 AP；
- 未标正例发现率；
- 伪正例精度。

最终分类：

- Top-1 Accuracy；
- Macro-F1；
- Balanced Accuracy；
- 类别混淆矩阵；
- 多随机种子均值与标准差。

### 14.3 关键证据链

理想结果应体现：

> 原始标注存在明显漏标  
> → PN 训练受到损害  
> → Ignore 或 Existing PU 能部分缓解  
> → Oracle 显著更优  
> → 现有方法与 Oracle 之间仍存在可改进空间。

### 14.4 停止条件

以下任一情况出现，都应考虑停止或重构：

- 漏标比例极低；
- 标注者对新增构件意见高度不一致；
- PN 与 Ignore 几乎无差异；
- Existing PU 已接近 Oracle；
- 局部任务有提升，但最终分类无明显变化；
- WikiChurches 标注语义与研究假设不一致。

## 17. 缺失机制设计

为了证明方法不仅适用于一种随机缺失，应模拟：

### 17.1 随机缺失

随机删除一定比例的局部标注。

### 17.2 类别相关缺失

部分风格或类别拥有更少局部标注。

### 17.3 构件相关缺失

小构件、稀有构件或难识别构件更容易漏标。

### 17.4 视角相关缺失

远景、侧视、遮挡图像的局部标注更少。

### 17.5 正例式代表性标注

每张图像只保留最典型的一个或少数构件框，模拟专家只标代表性证据的情况。

## 19. 消融实验

必须围绕核心创新展开，避免无意义堆模块。

### 19.1 区域监督消融

- 不使用局部监督；
- 仅使用框内正例；
- 框外全部作为负例；
- 框外全部忽略；
- 使用 PU 风险估计；
- 使用高可信正例扩展。

### 19.2 正例扩展消融

分别移除：

- 多视图一致性；
- 支持样本一致性；
- 混淆类别对比；
- 不确定性约束；
- 多尺度一致性。

### 19.3 Patch 校准消融

比较：

- 仅使用母体判别分数；
- 仅使用区域语义分数；
- 固定线性融合；
- 可学习门控融合；
- 乘法校准；
- 加法校准。

### 19.4 标注质量消融

## 27. Go / No-Go 决策标准

### Go

满足以下多数条件：

- 标注确实非穷尽；
- 漏标稳定且可量化；
- PN 明显弱于 Ignore 或 PU；
- Oracle 与现有 PU 仍存在明显差距；
- 局部监督改善能够传递到最终分类；
- 专项检索后仍存在明确方法差异。

### No-Go

满足以下任一关键条件：

- 标注本身较完整；
- 漏标率极低；
- PN 与 Ignore 无显著差异；
- Existing PU 已基本达到 Oracle；
- 局部任务提升无法改善分类；
- 候选机制已被近期工作完整覆盖；
- 研究只能形成建筑数据集上的简单应用扩展。

PyTorch Geometric 缺少 COO→CSR 算子而失败；启用

## 29. 2026-07-28 实验证据更新与 Proposal 转向

截至 `PAT-B-260728-001`，原始方法路线已完成停止性验证：

- 普通 nnPU/IPW 与保守高置信正例扩展均未超过 Ignore；
- TOGA 在 WikiChurches 冻结确认中为 1 胜 8 负；
- 官方构件框比匹配随机区域包含更多风格信息，信息探针通过；
- 但三代 positive-only 局部融合器均未通过 validation-only 停止门槛；
- canonical test 在全部开发过程中始终未加载。

最新 church-level 诊断发现：

- 90 个带框 train church 的 Global CLIP train→validation BA 从
  84.46% 降至 57.36%，分层置换 `p=0.00120`；
- Local residual BA 从 86.22% 降至 52.18%，`p=0.00070`；
- Gothic local recall 下降 65.43pp，偏移效应排名第 1；
- 全部 5,750 个 canonical-train church 的 global control 与 validation
  不显著偏移（`p=0.47965`）。

因此当前证据支持的不是“再设计一个更复杂的 PU adapter”，而是：

> 选择性局部标注可以包含强判别信息，但提供局部框的样本子集可能具有严重
> 覆盖偏差；在这种条件下，局部任务内增益无法稳定传递到独立 few-shot
> 识别终点。

后续有两种可辩护路径：

1. **诊断论文路径**：研究局部标注的信息性、代表性和 downstream
   transferability 三者为何分离，并建立相应审计协议；
2. **方法论文重启路径**：补标覆盖更具代表性的 church，或更换具有完整
   区域监督的数据集，再建立全新的开发/确认划分。

在数据条件改变前，WikiChurches 上停止继续调整 TOGA、PU、local adapter、
融合门控或随机种子。
