# Style guide

- Tone: restrained, empirical, conference-appropriate.
- Prefer “we test”, “the result supports”, and “under this protocol”.
- Avoid “novel” without naming the exact mechanism; avoid “first” unless a later complete audit supports it.
- Keep “attention hit rate” distinct from standard PCK.
- Always distinguish K0, from-scratch Random-K1, WarmStart-Identity, Permutation-Only, and PASAC.
- Report percentage-point differences, not ambiguous percent improvements.
- Every test claim must state whether it uses CUB OOF development or an official held-out test.
