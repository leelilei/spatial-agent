# Kickoff — Telephone (2026-06-19)

## Why this project exists
Spun out of 3-SMGA. The SMGA society-sim work converged on an honest negative (structured
memory ≈ GA once you remove a scenario-keyword cheat), and in doing so uncovered the real,
under-characterized phenomenon: **a fact-update degrades as it propagates through an
LLM-agent society** (stale-persistence, detail drift, version splitting). See
`../3-SMGA/sim/RESULTS.md` S5L-diag. Telephone studies THAT phenomenon directly.

## First concrete steps (proposed, not yet started)
1. **Reuse the engine**: bring `society.py` / `memories.py` / `llm.py` / `replay_eval.py`
   from `../3-SMGA/sim` into `sim/` (copy, then strip the SMGA-specific memory variants /
   scenario anchors that we proved were cheats; keep raw + GA-reflection as baselines).
2. **Define metrics cleanly** (`docs/plans/metrics.md`): fidelity, version-share,
   decay-vs-hops, corruption taxonomy — with a NON-CIRCULAR "received" definition.
3. **First measurement (M0)**: inject one ground-truthed update; measure the fidelity-decay
   curve at one connectivity / one model. Establish that decay is real and quantifiable.
4. **Then ablate** one governing variable at a time (connectivity, model capability,
   redundancy, authoritative re-broadcast, memory architecture).

## Reuse vs fresh
- REUSE: sim engine, embeddings (model2vec), the reproducibility/variance/replay rigor.
- FRESH: the framing, the claim, the metrics (truth-fidelity, not memory ranking), and the
  scenario design (built to MEASURE corruption, not to rank memory).
